# Agent 作業日誌 (2026-10-17)

## 一、 任務目標與上下文 (Context & Objectives)

* **修復與優化 `!farm` 農事播種的線上運行問題**：
  1. 遭攻擊或新指令介入時無法及時中斷，Executor 拋出 `Action FarmPlant cancellation confirmation timed out after 1000ms` 並導致整個系統進入 FAULTED 卡死。
  2. 耕地播種執行時出現 `placeBlock error: Error: Server refused to place wheat_seeds: the block is still air`，播種失敗。
  3. 農事執行時在原地重複「空揮」，且不會搜尋下一塊可用耕地。
  4. 種子與最佳武器高速反覆切換（Priority Thrashing）。
  5. 邊走邊種導致位移干擾或碰撞箱重疊。
  6. 播種連續失敗時缺乏熔斷機制（Circuit Breaker）。
  7. 移除完成農事後強制返回集合點（`ReturnToRally`）的設計，任務完成或中止時原地進入 `IDLE`。

## 二、 核心問題根因分析與技術修復 (Root Causes & Solutions)

### 1. 中斷超時卡死修復 (`FarmPlant cancellation confirmation timed out after 1000ms`)
* **根因**：
  * 原 `isStopped()` 實作為 `!active && !inFlight`。
  * 當 Action 正在等待非同步網路通訊或方塊放置時，`inFlight` 為 `true`。若非同步操作耗時超過 1000ms，Executor 的 `advanceTick` 會判定取消超時，將狀態轉為 `FAULTED`。
  * 在 `FAULTED` 狀態下，Executor 會全面拒絕所有後續動作（包括 `!stop`、`!come` 與戰鬥反擊），導致 Bot 完全凍結。
* **修復**：
  * `cancel()` 觸發時將 `active = false` 並即時停止 Pathfinder。
  * `isStopped()` 修正為回傳 `!active`，使 Arbiter 搶佔與 Executor 能在當前 Tick 立即確認釋放資源。
  * 非同步操作前後全面加入 `if (!active || !ctx.isActive()) return;` 檢查，取消後靜默終止，不污染狀態也不噴警告日誌。

### 2. 播種失敗與方塊碰撞修復 (`the block is still air`)
* **根因**：
  * **實體碰撞阻礙**：Minecraft 伺服器禁止玩家實體與欲放置作物的空間碰撞。若 Bot 站得過近（如 XZ 差 $< 0.8$ 格且處於作物高度），玩家碰撞箱（寬 0.6、高 1.8）侵入作物方塊，伺服器會拒絕放置。
  * **放置機制差異**：Mineflayer 的 `placeBlock` 是針對實體方塊（要求放置後方塊狀態立即改變），且會等待伺服器 blockUpdate 回應。在 PaperMC 上種子為物品，常因時序不一致或嚴格檢查拋出 `Server refused to place ...: the block is still air`。
* **修復**：
  * **作物碰撞箱檢驗**：在 `farmPlant.update()` 加入碰撞箱重疊偵測；若 Bot 侵入作物方塊空間，主動導航後退至安全距離（1.6 格外）再播種。
  * **採用 `activateBlock`**：依照 `docs/references/minecraft-bots/skills.js` 最佳實踐，優先使用 `bot.activateBlock(farmlandBlock)` 右鍵觸發耕地播種，並主動調用 `bot.swingArm('right')` 補齊揮手動畫；保留 `placeBlock` 作為向下相容 fallback。

### 3. 重複「空揮」與耕地黑名單冷卻機制
* **根因**：
  * 播種失敗後，由於該耕地上方仍為空氣，下一 Tick 行為樹的 `getAvailableFarmland` 又立刻挑選同一塊耕地，導致 Bot 在原地對著同一塊耕地無限重複空揮。
* **修復**：
  * 在 `Perception` 中實作 `farmlandCooldowns: Map<string, number>` 暫時黑名單與冷卻機制。
  * 於 `createFarming` 加入 `onFarmlandFailed` 回呼；一旦某耕地播種失敗或超時，即刻將該座標加入 30 秒冷卻。
  * 播種成功時亦暫時記錄冷卻，避免伺服器封包延遲時重複挑選。
  * `findAvailableFarmland` 搜尋時主動過濾冷卻中的座標；若目前耕地失敗，自動尋找下一個可用耕地。

### 4. 種子與武器高速切換與動態優先級架構
* **根因**：
  * 原先 `EquipBest`（整理裝備/拿最好的劍）優先級高達 50，而 `FarmPlant` 優先級為 30。
  * 當 `FarmPlant` 換上種子時，Bot 手持武器傷害歸零，導致維護子樹的 `EquipBest` 立即搶佔並把獄髓劍切回手持；下個 Tick `FarmPlant` 又把種子換回，形成 50ms 一次的切換風暴。
* **修復**：
  * 拒絕在各節點內部寫死 ad-hoc 特判。
  * 建立統一的 `calculateActionPriority(actionType, snapshot)` 機制：
    * 平時和平期 `EquipBest` 作為閒暇整理，基準優先級降至 15。
    * 遇敵戰鬥時（`snapshot.world.threats.length > 0`），`EquipBest` 動態加成至 75，優先確保迎敵武器。
    * 當工作模式啟用時（如 `snapshot.intent.mode === 'FARM'`），工作動作（如 `FarmPlant`）動態加成 +10（優先級達 40），壓制休閒維護動作。

### 5. 嚴格依序播種流程（定點停步 -> 播種檢驗 -> 再移動）
* **修復**：
  * `farmPlant` 重構為明確的雙階段狀態機（`APPROACH` -> `PLANTING`）：
    * `APPROACH`：計算耕地前方 1.5 格的安全站立點，導航抵達後**完全停止所有移動與物理控制**（`setControlState` 清空、清空 pathfinder goal）。
    * `PLANTING`：完全靜止下轉頭對準耕地方塊，手持種子調用 `activateBlock` 並揮手，延遲 150ms 檢驗方塊狀態改變或種子數量減少。
    * 嚴格確認播種結果後才結束當前 Action，允許下一次移動。

### 6. 連續 5 次播種失敗熔斷機制（Circuit Breaker）
* **修復**：
  * `bot.ts` 追蹤農事連續失敗計數器 `consecutiveFailures`。
  * 播種成功或接收新 `!farm` 指令時歸零；播種失敗時遞增。
  * 達連續 5 次失敗時觸發熔斷：
    * 廣播聊天訊息：`Farming failed: 5 consecutive planting attempts failed.`
    * 清除農事任務，狀態直接切換至 `IDLE`。

### 7. 移除任務完成返回中心點（`ReturnToRally`）
* **修復**：
  * 從 `ACTION_POLICY`、行為樹 `workArea` 子樹、`bot.ts` 中完全移除 `ReturnToRally` 動作與政策定義。
  * 當農事播種全部完成、無可用種子、無可用耕地或排班超時，直接切換至 `IDLE`。
