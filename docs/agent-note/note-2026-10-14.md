# Stage 1 & 2 審核交接與後續階段實作指引 (2026-10-14)

## 一、 Stage 1 & 2 審核結論 (Audit Summary)

* **規範遵循度**：
  * 全專案已升級至 TypeScript (`strict: true`)，`tsconfig.json` 配置 `NodeNext` 與 `noUncheckedIndexedAccess`。
  * `src/bt/**` 完全零副作用，無 `mineflayer` 依賴、無 `bot` 實例、無 `async/await`，僅同步消費 `snapshot` 回傳 `{ status, requests }` (`[RULE-02]`)。
  * `src/execution/arbiter.ts` 落實 All-or-Nothing 原子分配與優先級仲裁，無 Lock Escalation (`[RULE-03]`)。
  * `src/execution/executor.ts` 具備 1 個 `physicsTick` (50ms) Control-Plane Fence，搶佔舊動作時不等待懸空 Promise 完成 (`[RULE-05]`)。
  * `ActionContext.isActive()` 嚴格校驗 `generation`、`runId`、`token` 與 `status === 'RUNNING'` (`[RULE-04]`)。
  * `src/bot.ts` 在 `death` 與 `end` 事件時觸發重置，遞增 generation 並清空所有資源鎖與執行期狀態 (`[RULE-09]`)。
* **驗收結果**：
  * 靜態檢查：`pnpm run build` 通過，零型別錯誤。
  * 單元測試：`pnpm test` 通過 21 項測試（覆蓋 BT 節點、仲裁原子性、50ms Fence、懸空 Promise 隔離、管線事件防重入、生命週期重置與 VOICE 限速佇列）。
  * 實機測試：`test/integration/stage-two-paper.test.ts` 驗證 Paper 伺服器連線、指令切換意圖與預設回落至 `Idle`。

## 二、 現有架構之工程優化點 (Architecture Optimizations)

* **快照複製效能與 GC 壓力控制**：
  * 現況：`src/blackboard.ts` 每 100ms 執行 `freezeDeep(structuredClone(state))`。
  * 規範：進入 Phase 4（敵對生物）與 Phase 6（掉落物）後，世界實體量上升。`src/perception.ts` 必須維持採集半徑與容量邊界，嚴禁無界複製：
    * 敵對生物採集半徑限縮於 32 格（`THRESHOLDS.observationRadius`），最多保留距離最近之 16 隻實體。
    * 掉落物採集半徑限縮於 5 格（`THRESHOLDS.pickupRadius`）。
* **實體參照（Entity ID vs. Object Reference）轉譯防護**：
  * 現況：`Blackboard` 僅記錄 `entityId` 與純數值座標，確保資料中樞無外部狀態持有。
  * 規範：`src/actions/`（如 `GoalFollow`、`bot.attack`）使用 Mineflayer API 時，必須透過 `bot.entities[targetId]` 取用實體。
  * 防護：取用前必須執行防禦性空值檢查，防範目標在同個 Tick 瞬間死亡、被拾起或 Despawn。
* **文件版本一致性維護**：
  * `docs/rules/rule-JS-agent.md` 與 `docs/rules/rules-javascript.md` 屬初期 CommonJS 舊稿，實作標準以 `docs/sys-design/system-design-v1.1.md` 與 `docs/implement-plan.md` 為準。

## 三、 後續 Stage 實作關鍵與避坑指引 (Stage 3–8 Reminders)

### Phase 3: 跟隨功能 (Follow Functionality)
* **Goal 抖動防護 (`[RULE-07]`)**：
  * 使用 `bot.pathfinder.setGoal(new GoalFollow(masterEntity, range), true)`。
  * 因 `dynamic = true` 已由 Pathfinder 物理 Tick 追蹤，同一個 `runId` 期間**嚴禁在 `update()` 重複呼叫 `setGoal()`**。
  * 停止時唯一允許呼叫 `bot.pathfinder.setGoal(null)`。
* **嚴格雙門檻遲滯 (Hysteresis)**：
  * `NormalFollow`：進入條件為距離 `> 5` 格，退出條件為距離 `<= 3` 格。
  * `CatchUpFollow`：進入條件為距離 `> 16` 格，退出條件為距離 `<= 6` 格。

### Phase 4: 自動防禦反擊 (Self-Defense & Combat)
* **目標鎖定安全推斷 (`[RULE-08]`)**：
  * 僅針對身旁 8 格內的「敵對生物（Hostile Mob：殭屍、骷髏、蜘蛛、苦力怕等）」反擊。
  * 禁止在無明確惡意指令下攻擊附近玩家、寵物或中立生物。
* **換裝與揮砍的非同步隔離 (`[RULE-04]`)**：
  * 拔刀裝備 `await bot.equip(bestWeapon, 'hand')` 前後行必須檢查 `if (!ctx.isActive()) return;`。
  * 嚴禁安裝 `mineflayer-pvp`；自行使用原生時間間隔（約 550ms）執行 `bot.lookAt` 與 `bot.attack`。
* **脫戰邊界**：
  * 目標死亡、距離 `> 16` 格或距離主人 `> 24` 格時自動結束動作釋放資源。

### Phase 5: 殘血逃跑功能 (Emergency Retreat)
* **All-or-Nothing 整組搶佔**：
  * `Retreat` (Priority 100) 請求 `{MOVE, LOOK}`，衝突時 Arbiter 必須將 `Combat` (Priority 80) 整組終止，同步釋放 `{HAND, INVENTORY}`。
  * 確保逃跑觸發 50ms 後無殘留攻擊或揮手封包。
* **逃跑退出時間遲滯 (Safe-Time Hysteresis)**：
  * 退出條件需同時滿足「距離威脅 `>= 18` 格且持續安全達 3 秒（`THRESHOLDS.retreatSafeMs`）」或「`HP >= 10`」，防止剛出邊界立刻回頭。

### Phase 6: 自動鄰近撿拾 (Opportunistic Pickup)
* **不可達目標冷卻處理**：
  * `src/perception.ts` 掃描掉落物時過濾 `snapshot.runtime.cooldowns` 未過期 ID。
  * 若逾時 4 秒或收到 `noPath`，Action 回傳 `FAILURE`，由 `executor` 寫入 30 秒冷卻表。

### Phase 7: 身體維護：自動裝備與進食 (Maintenance: Eat & Equip)
* **動態挖掘降級 (Dynamic `canDig` Downgrade)**：
  * `Follow` 單獨運行時允許 `movements.canDig = true`。
  * 一旦 `Eat` 或 `EquipBest` 取得 `{HAND, INVENTORY}`，`navigation` 模組必須立即將 `movements.canDig = false`，避免揮手挖方塊打斷進食封包。
* **`consume()` 懸空 Promise 強制隔離 (`[RULE-05]`)**：
  * 進食被搶佔時呼叫 `bot.deactivateItem()`；50ms 後資源強制移交，原 `bot.consume()` 的 Promise 依賴 `ctx.isActive()` 攔截丟棄。

### Phase 8: 綜合壓力與交接驗收 (Integration Harness)
* 撰寫 `test/integration/handoff-harness.ts`，驗證「邊跑邊吃」、「進食遇襲搶佔拔劍」、「殘血撤退整組中斷戰鬥」以及長時間無記憶體洩漏（10 分鐘 10Hz Tick 耗時 `< 5ms`）。
